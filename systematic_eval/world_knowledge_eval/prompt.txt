You are an expert reviewer for a research project on semantic SQL rewrites. In that project, an LLM invents *rewrite rules* for a specific database (here: the `{dataset}` database, whose schema is given below). A rule adds extra WHERE predicates to a query: whenever the predicates in `requires` already hold, the predicates in `implies` may be added. The rules are non-equivalent in general SQL, but claimed to preserve the result *on this particular database instance*, and they are meant to make the query faster.

Your job is to judge, for ONE validated rule, HOW STRONGLY it relies on real-world domain knowledge, as opposed to being a pattern that could be discovered from the database instance alone.

Definitions — the two poles of the scale:

- DB-DERIVABLE (low world-knowledge): The implication is essentially a data property that an automatic system could find by scanning/profiling the database — e.g. a simple functional dependency or information that is absolutely clear from the sql query itself. No knowledge of what the data *means* is required for making sure the rule is (almost) always correct;

- WORLD-KNOWLEDGE-DEPENDENT (high world-knowledge): The implication only makes sense (and is only plausibly result-preserving) because of real-world facts about the domain that are NOT visible from the schema or a naive data scan. A profiling tool without domain understanding would not propose this shortcut or could not trust it.

Most rules are a mix; place them on the 1–5 scale accordingly:
  1 = fully DB-derivable; a profiler would find and trust this from the data alone.
  2 = mostly DB-derivable; only a thin layer of domain framing.
  3 = genuinely mixed; the data hints at it, but domain knowledge is needed to justify/scope it.
  4 = mostly world-knowledge; the data alone would not justify or safely scope the rule.
  5 = fully world-knowledge-dependent; the shortcut is an external-fact judgement, not a data property.

Consider the rule's own logic (its `requires` -> `implies`), the schema below, and the model's stated rationale. Judge the *actual* dependence on world knowledge, not how confidently the rationale is phrased — a rationale can invoke "real-world domain knowledge" for something that is in fact just a functional dependency, and vice versa. If the rationale is missing, judge from the rule and schema alone.
